Status: exit criteria measured. Not merged: `core:storage` is
[PR #10](https://github.com/sameerkrmishra/jotter/pull/10), open with CI green and
no human review ([PLAN.md §9](../PLAN.md#9-development-model-agent-swarm)). The

## What was delivered

- **`core:model`** (PR #7): notes, tags, revisions and the hybrid logical clock.
  No I/O.
- **`core:sqlite`** (PR #8): a SQLDelight driver over the bundled SQLite.
- **`core:storage`** (PR #10): notes, tags, pin, archive, trash, delete forever,
  the revision table and full-text search, in schema version 1.
- **`linuxX64` targets** for the shared modules (PR #6).

## Demo

M1 is a set of libraries with no app of its own, so this demo goes through the CLI
from M2. You need the prerequisites in [CONTRIBUTING.md](../../CONTRIBUTING.md).
`XDG_CACHE_HOME` keeps the CLI's class data archive out of `~/.cache/jotter`, and
`JOTTER_DB` keeps the notes out of your real database.

```sh
./gradlew :app:cli:installDist
scratch=$(mktemp -d)
export JOTTER_DB="$scratch/notes.db" XDG_CACHE_HOME="$scratch/cache"
jotter=app/cli/build/install/jotter/bin/jotter

id=$($jotter add --title "Groceries" --tag Shopping "Milk and café au lait")
$jotter add --tag Work "Plan the release"
$jotter list              # both notes, newest first
$jotter list --tag Work   # only the second note
$jotter search cafe       # finds "café": case and accents fold
$jotter tags              # Shopping 1, Work 1
$jotter show "$id"        # every field of the first note
$jotter add "   "         # fails: jotter: the note is empty
```

To see the benchmark and the gate:

```
./gradlew :core:storage:searchBenchmark
./gradlew check
```

Remove the scratch directory with `rm -r "$scratch"`.

## Decisions made

- [ADR-0006](../adr/0006-native-compatible-shared-modules.md): shared modules
  build and test on `linuxX64`, to keep a native CLI cheap.
- [ADR-0002](../adr/0002-sqlite-via-sqldelight.md): the driver lives in
  `core/sqlite`, over androidx `sqlite-bundled`.
- [ADR-0003](../adr/0003-revision-dag-and-three-way-merge.md): refinements from
  building `core:model`: what a stamp includes, how last-writer-wins stamps carry
  over, and how the clock treats far-future times.
- [ADR-0009](../adr/0009-import-preserves-source-timestamps.md): imported notes keep
  their source times. It was decided before the schema froze, because it could have
  changed the schema. It did not.
- Without an ADR, in the [`core:storage` README](../../core/storage/README.md): every
  write is one `BEGIN IMMEDIATE` transaction, `seq` gives revisions a stable local
  order, and a file without Jotter's `application_id` is refused.

## Known limitations and what was not verified

- **Android.** The device tests of `core:sqlite` passed 51 of 51 on API 26 and 36
  emulators, by hand, for PR #8. They were not run after the later changes to
  `core:sqlite` (the open path and migrations). `core:storage` has never run on
  Android: its host tests are disabled, and no CI job runs device tests until M5.
- **One machine.** The timings come from one workstation. They are not checked in
  CI, and the benchmark is not part of `check`.
- **Short searches.** A one-letter prefix misses 50 ms. The UI waits for a second
  character.
- **Coverage is JVM only.** Kover cannot measure Kotlin/Native. The figures above use
  the JaCoCo engine, adopted in M2. PR #10 reported 99.86% of lines and 97.84% of
  branches overall with Kover's default engine, before the later commits.
- **No merging.** A note has one head until M3.
- **Schema version 1** freezes once M1 closes, and M1 closes with PR #10. A database
  from before that PR's `application_id` change is refused and must be recreated.
