## What was delivered

- **`app:android`** (new): the screens of `app:shared-ui` in one Activity, for Android 8.0
  (API 26) and later, targeting Android 16 (API 36)
  ([README](../../app/android/README.md), ADR-0018).
  - **Share target.** `ACTION_SEND` of `text/plain` or `text/markdown` becomes a new note;
    the subject becomes the title. A file or image alone is refused in plain words; text over
    the note cap is refused whole, never cut. A window that Android brings back after ending
    the process does not save the note twice.
  - **Sync with WebDAV and the PC hub only.** The Sync screen says, in plain words, that
    folders cannot be used on Android yet and why.
  - **Background sync.** One `SyncScheduler` per process, as on the desktop: a round on start,
    each time the app comes to the screen, 5 s after edits and on "Sync now". WorkManager's
    `SyncWorker` runs every 15 minutes with a network while a backend exists, and once after
    the app leaves the screen or a text is shared; it waits for a round of the scheduler, so
    the backoff and the wait after a refused password are the scheduler's.
  - **Secrets in the Keystore.** `SealedFileSecretStore`: one AES-256-GCM key in the Android
    Keystore, each secret with a fresh IV and its name as associated data, in one file in
    `noBackupFilesDir`. Password and token fields ask for a password keyboard without
    autocorrection.
  - **Backups.** Auto Backup and device transfer copy the notes database only, and a cloud
    backup only if it is end-to-end encrypted. On Android 8, nothing.
  - **The hub only over Tailscale.** A hub's token leaves the phone only to loopback, or while
    a VPN holding a Tailscale address carries the app (`AndroidTailnet`, `TailnetCheck` in
    `app:sync`).
- **`app:sync`**: `SyncScheduler.syncAndWait` for a background job; `TailnetCheck`, which lets
  an app refuse a hub off the tailnet and give the hub client its own HTTP engine and name
  lookup (`PeerTransport`); `HubForAndroidTest`, the PC's half of the end-to-end test.
- **`app:shared-ui`**: Back, drafts kept when the app leaves the screen
  (`AppViewModel.keep`), forms that stack below 600 dp, and the password keyboard for secret
  fields.
- **Device tests for the shared modules** (#16). `jotter.android-device-test` gives a
  multiplatform module an `androidDeviceTest` source set over `commonTest`, run by
  `connectedAndroidDeviceTest`. The 11 shared library modules pass on API 26 and 36 emulators
  (893 cases each, locally). Device-only tests show that the bundled SQLite 3.50.1 with FTS5 is
  what runs, that every saved schema migrates on a device, and that a local folder in the app's
  storage and in shared storage holds under three racing processes, by rename under an `fcntl`
  lock, as an app has no hard links. The run found that Android's `Files.getFileStore` throws
  `SecurityException`, which escaped `LocalFolderBlobStore.writeNew`; it is fixed.
- **The review's follow-ups** (#19):
  - **Hub names are looked up through the VPN.** `PeerBlobStore` looked the hub's name up with
    the system's DNS, so a MagicDNS name could be asked of the mobile network if the VPN
    dropped. Now the lookup is `Network.getAllByName` on Tailscale's network, for the store,
    OkHttp's `dns` and the socket factory alike; without the network the hub is unreachable
    with the "not on your tailnet" reason.
  - **A robust hub CPU test.** `HubExhaustionTest` sums the CPU time of the hub's own threads
    (`jotter-hub-*`, through `ThreadMXBean`) instead of the process's, so other work on a busy
    machine no longer fails it, and checks that the connection threads stay within the limit.
    No production code changed.
- **F-Droid and the release build** (#18, ADR-0019):
  - The version is two literals in `gradle.properties`, `jotter.versionName` (`0.1.0`) and
    `jotter.versionCode` (`1`), read by `app:android` and `app:desktop`.
  - The release APK is unsigned unless `JOTTER_KEYSTORE` is set; signing refuses to run with
    the configuration cache. No Google dependency metadata block, no VCS info file, no R8.
  - `app/android/scripts/reproducible-build.sh` builds the unsigned release APK twice from
    `git archive` copies and compares; the `reproducible` workflow runs it with Temurin and
    Zulu JDK 21.
  - The store listing in `fastlane/metadata/android/en-US/` (title, descriptions, changelog
    for version code 1, icon; no screenshots), a draft fdroiddata recipe, an inclusion check
    and a dependency audit in [docs/fdroid](../fdroid/README.md), and the maintainer's release
    steps in [docs/releasing.md](../releasing.md).
  - The manifest removes emoji2's `EmojiCompatInitializer`, so the app never asks a font
    provider such as Google Play Services for an emoji font.
- **CI**: the `android-device` job (API 26 and 36) runs `connectedAndroidDeviceTest` and
  `:app:android:connectedDebugAndroidTest` on every pull request; the `reproducible` workflow;
  `check`'s timeout is 60 minutes.

### Checklist for the maintainer: phone and PC

Nothing here has run on a real phone, over a real tailnet, with Tailscale's Android app or
against a real WebDAV server from Android. Write down what each step shows, especially any
refusal or message: it is the result. Passwords and tokens are typed into the apps or at a
prompt, never on a command line.

**What you need:** the PC with this repository, the Android SDK (for `adb`) and `secret-tool`;
an Android phone, 8.0 or later, with USB debugging on; Tailscale on both, logged in to the same
tailnet; a WebDAV folder that works with Jotter. If the [M4 checklist](m4.md#checklist-for-the-maintainer-mailboxorg)
has not been run, run its steps 1 to 4 first: they make the app password and the folder, find
its URL, and set the store up from the PC. Use a second app password for the phone.

1. **Build and install the app.** Either the debug APK:

   ```sh
   ./gradlew :app:android:assembleDebug
   adb devices                          # the phone's serial
   adb -s SERIAL install -r app/android/build/outputs/apk/debug/android-debug.apk
   ```

   or a release signed with your own key, as in [docs/releasing.md](../releasing.md) step 3
   (the password is read with `read -rs`, not typed on the command line), installed with
   `adb -s SERIAL install -r app/android/build/outputs/apk/release/android-release.apk`. Both
   have the same application id and different signatures: to switch from one to the other,
   uninstall first, which deletes the phone's notes. Step 9's database copy needs the debug
   build.
2. **The PC.** Build the desktop app and the CLI, as in M4's step 4, with a database of its
   own for this run, and start the app in the background from that shell, so that it gets
   `JOTTER_DB` and the shell stays free for the CLI:

   ```sh
   ./gradlew :app:cli:installDist :app:desktop:createDistributable
   alias jotter="$PWD/app/cli/build/install/jotter/bin/jotter"
   mkdir -p ~/jotter-m5
   export JOTTER_DB=~/jotter-m5/notes.db
   app/desktop/build/compose/binaries/main/app/jotter/bin/jotter &
   ```

   Run every later `jotter` command in this shell. In any other terminal, run the `alias` and
   `export JOTTER_DB=...` lines first (from the repository root): without `JOTTER_DB`, the CLI
   reads your default database, and `jotter conflicts` printing nothing there proves nothing.

   If M4's run set up the WebDAV store with another database, add it here too (Sync, "Add
   server", or `jotter backends add webdav 'URL' --user NAME` without `--new`, which asks for
   the password).
3. **Turn the hub on.** `tailscale ip -4` on the PC prints its Tailscale address, such as
   `100.101.102.103`. In the app: Sync, "This PC as a hub". Keep the hub folder (by default
   `$XDG_DATA_HOME/jotter-hub`) or choose another, set "Listen on" to that Tailscale address
   (the default is `127.0.0.1`, which the phone cannot reach), keep the port (47734), and press
   "Turn hub on". The hub's folder appears in the backend list as a local folder: the PC syncs
   with it directly. Enter `Phone` in "Device to pair" and press "Pair device": the token is
   shown once. Leave it on screen.
4. **Pair the phone over Tailscale.** On the phone, start Tailscale and check that it is
   connected. Open Jotter, Sync. Enter the PC's Tailscale address in "PC hub address" and the
   token in "Pairing token", and press "Add PC hub". It must be added without a "not on your
   tailnet" refusal. Close the token dialog on the PC. Also check the refusal: turn Tailscale
   off on the phone and press "Sync now"; the hub must show as unreachable with a plain reason
   about Tailscale. Turn Tailscale on again.
5. **The hub leg.** On the PC, add a note `Packing` with the lines `passport` and `charger`;
   it syncs 5 s after typing stops, or press "Sync now". On the phone, press "Sync now" on the
   Sync screen: the note is there, and the hub shows its last sync and no issue. Edit it on the
   phone (add `adapter`), press Home within 5 s and lock the phone: the job after leaving the
   screen should send it. On the PC, the edit must arrive within a few minutes ("Sync now").
6. **The WebDAV leg.** On the phone, in Sync: the WebDAV folder's URL, user name and the
   phone's app password, then "Add server". It must be added without the "Set this server
   folder up for Jotter?" question, as the PC set the store up. Then, on the PC, "Turn hub
   off", so that only WebDAV can carry a change. Add a note `WebDAV only` on the phone, sync;
   on the PC, sync: it is there. Edit it on the PC, sync; on the phone, sync: the edit is there.
   The hub shows as unreachable on the phone meanwhile. Turn the hub on again.
7. **A conflict, with the phone offline for a while.** Turn on airplane mode on the phone.
   On the phone, change `charger` in `Packing` to `sunscreen`. On the PC, change it to
   `travel plug`, and sync. Leave the phone offline for at least an hour; the app should keep
   working, and its Sync screen should say that neither backend can be reached, without
   errors about the notes. Turn airplane mode off and press "Sync now" on the phone, then sync
   the PC. Both must show `Packing` under "Needs attention" as conflicting edits, and
   `jotter conflicts` on the PC must list it. Answer it on the phone (any of the four answers),
   sync both, and it must be gone on both, with the same text.
8. **Background sync.** Leave the phone locked and untouched for 30 minutes or more. On the PC,
   add a note `Background`, and sync. Unlock the phone, turn on airplane mode **before**
   opening Jotter (opening it starts a sync), then open it: `Background` is there only if a
   background job fetched it. Write down whether it was, and how long the phone had been
   locked. Turn airplane mode off.
9. **Declare convergence** when, after a final "Sync now" on the phone and a sync on the PC:
   - on the phone, the Sync screen shows both the hub and WebDAV with a recent last sync and
     no issue, and nothing is under "Needs attention";
   - on the PC, after quitting the desktop app (which also stops the hub), `jotter sync`
     prints `synced` for the hub's folder and WebDAV, `jotter backends status` shows
     `reachable: yes` and no `issue:` lines, and `jotter conflicts` prints nothing;
   - the note lists on both hold the same notes with the same text; with many notes, compare
     exports: `jotter export ~/jotter-m5/pc-export` on the PC, and, with the debug build only,
     a copy of the phone's database exported the same way:

     ```sh
     mkdir -p ~/jotter-m5/phone
     adb -s SERIAL shell am force-stop io.github.sameerkrmishra.jotter   # no writes during the copy
     adb -s SERIAL exec-out run-as io.github.sameerkrmishra.jotter cat databases/jotter.db > ~/jotter-m5/phone/notes.db
     adb -s SERIAL exec-out run-as io.github.sameerkrmishra.jotter cat databases/jotter.db-wal > ~/jotter-m5/phone/notes.db-wal
     JOTTER_DB=~/jotter-m5/phone/notes.db jotter export ~/jotter-m5/phone-export
     diff -r ~/jotter-m5/pc-export ~/jotter-m5/phone-export
     ```

     Stopping the app first keeps the database and its `-wal` consistent with each other; if
     `jotter.db-wal` is missing, the database alone is the whole copy. The two `adb` copies were
     run on an emulator for this note, without the `force-stop`; exporting such a copy with the
     CLI was not (see the demo).
   - in the WebDAV folder and the hub's folder, `jotter/formats/1-json+gzip.json` and one
     folder per device under `jotter/devices/`: the PC's and the phone's.
10. **Optional.** Unpair `Phone` on the PC: the phone's next sync must show the hub as
    refusing its token and ask for a new one, and wait 30 minutes before trying it again.
    Revoke the phone's app password at the WebDAV provider: the same for WebDAV.
11. **Afterwards.** Remove the backends on the phone (Sync, remove) and on the PC (`jotter
    backends remove ID`), unpair the phone, turn the hub off, revoke the phone's app password,
    and delete `~/jotter-m5` and the hub's folder if they are not wanted.

### The debug APK on a headless emulator

An emulator of its own, in a directory of its own, on its own port, with no window. Make the
directory first: if `ANDROID_AVD_HOME` does not exist, `avdmanager` writes to
`~/.android/avd` instead.

```sh
export ANDROID_HOME=~/Android/Sdk
export ANDROID_AVD_HOME=$PWD/build/m5-avd
mkdir -p "$ANDROID_AVD_HOME"
echo no | "$ANDROID_HOME/cmdline-tools/latest/bin/avdmanager" create avd -n m5 \
    -k 'system-images;android-36;default;x86_64' -d pixel
"$ANDROID_HOME/emulator/emulator" -avd m5 -port 5750 -no-window -no-audio -no-boot-anim \
    -no-snapshot -gpu swiftshader_indirect > build/m5-emulator.log 2>&1 &
adb=$ANDROID_HOME/platform-tools/adb
$adb -s emulator-5750 wait-for-device shell getprop sys.boot_completed   # 1 once booted

./gradlew :app:android:assembleDebug
$adb -s emulator-5750 install -r app/android/build/outputs/apk/debug/android-debug.apk
    # Success
$adb -s emulator-5750 shell am start -W \
    -n io.github.sameerkrmishra.jotter/.app.android.MainActivity
    # Status: ok, LaunchState: COLD
```

Share a text to it, as a browser would:

```sh
$adb -s emulator-5750 shell am start -W -a android.intent.action.SEND -t text/plain \
    --es android.intent.extra.SUBJECT Reading \
    --es android.intent.extra.TEXT "'https://example.org/article'" \
    -n io.github.sameerkrmishra.jotter/.app.android.ShareActivity
```

## Decisions made

ADR-0018 and ADR-0019 are Proposed: written and reviewed by agents, not accepted by the
maintainer. Decisions marked **(orchestrator)** were made by the orchestrator on the
maintainer's behalf, for review at the end of the project
([PLAN.md §9](../PLAN.md#9-development-model-agent-swarm)). Each was checked against the code
at `7094025`.

The app:

- **(orchestrator)** [ADR-0018](../adr/0018-android-app.md): **no local folders on Android in
  v1.** On Android 10 and later an app reaches shared storage and USB drives only as
  `content://` documents, which have no hard links, no `fcntl` locks, no rename that refuses an
  existing target and no way to tell an unplugged drive from an empty folder, all of which
  ADR-0012's guarantees rest on. A folder in the app's own storage would reach no other device.
  The Sync screen says so (`SyncControls.foldersUnavailable`; seen in the demo).
- **(orchestrator)** ADR-0018: **the Keystore key is usable after the first unlock.**
  `keystoreKey` sets neither `setUserAuthenticationRequired` nor `setUnlockedDeviceRequired`,
  because WorkManager runs background sync while the screen is locked, often for hours, and
  such a key would fail every such sync. The cost: on a phone stolen after its first unlock,
  whoever can run code as Jotter can use the key, which the sandbox and the lock screen
  prevent.
- **(orchestrator)** ADR-0018: **Android 8 backs up nothing.** API 26 and 27 cannot require a
  backup to be encrypted on the device, so `res/xml/backup_rules.xml` excludes every domain.
  From Android 9, `res/xml-v28/backup_rules.xml` and `data_extraction_rules.xml` include only
  `jotter.db` and its `-wal`, with `clientSideEncryption` or
  `disableIfNoEncryptionCapabilities`.
- **(orchestrator)** ADR-0018: **the hub client is bound to the VPN, with route checks.**
  `100.64.0.0/10` is also carriers' CGNAT space, so the token goes out only while a VPN with a
  Tailscale address carries the app. Then the hub's sockets are bound with `Network.bindSocket`
  and connect only to an address the VPN's routes cover, read again at each connection, and,
  since #19, the hub's name is looked up with `Network.getAllByName` on the same network
  (`Tailscale.kt`, `TailnetSockets.kt`). So a VPN that drops mid-sync makes requests fail
  instead of leaving by the mobile network, and a MagicDNS name never goes to the carrier's
  DNS. CIO takes no socket factory, so the hub uses Ktor's OkHttp engine on Android.
- **(orchestrator)** Without an ADR, in the [`app:android` README](../../app/android/README.md)
  and `BackendsScreen` (`KeyboardType.Password`, `autoCorrectEnabled = false`): **secret fields
  ask for a password keyboard** without autocorrection, so that a keyboard neither learns nor
  syncs passwords and tokens. `MainActivityTest` checks `EditorInfo.inputType` on a device.
- **(orchestrator)** Without an ADR, in the manifest and [docs/fdroid](../fdroid/README.md):
  **emoji2's font provider is removed** (`EmojiCompatInitializer`, `tools:node="remove"`),
  because it asks a system font provider, on most phones Google Play Services, for an emoji
  font, which an F-Droid reviewer may question. Compose then draws emoji with the system font;
  one newer than the phone's Android shows as a blank box.
- **(orchestrator)** ADR-0018: tests reach a hub on the host through `adb reverse` to
  loopback, not `10.0.2.2`, which the client refuses like any LAN address; no test exception
  was made to the address rule.
- **(orchestrator)** ADR-0018: one scheduler per process, and a `SyncWorker` that always
  succeeds, so that WorkManager's backoff does not stack on the scheduler's.

The release build:

- **(orchestrator)** [ADR-0019](../adr/0019-release-builds.md): **R8 is off for v1**
  (`isMinifyEnabled = false`), because it would need keep rules for Ktor's and kotlinx's
  reflection and a release build tested on devices, which CI's device tests (debug builds) are
  not. The APK is about 16 MB.
- **(orchestrator)** ADR-0019: **the version is two literals** in `gradle.properties`, because
  F-Droid's update checker reads each with a regular expression (`UpdateCheckData`) and cannot
  compute a code from the name, and anything from the clock or the commit makes builds differ.
  The build checks that the name is `MAJOR.MINOR.PATCH` and the code positive.
- **(orchestrator)** ADR-0019 and [docs/releasing.md](../releasing.md): **release signing is
  outside the repository.** Only `JOTTER_KEYSTORE` and the `JOTTER_KEY*` variables sign; CI and
  F-Droid build unsigned. With `JOTTER_KEYSTORE` set, the build **refuses the configuration
  cache**, which would store the passwords with the build's configuration
  (`app/android/build.gradle.kts`). With `minSdk` 26, AGP signs with v2 only, so the signed APK
  is the unsigned one plus a signing block, which F-Droid can verify.
- **(orchestrator)** ADR-0019 and `reproducible.yml`: **the reproducible job's path filter.** It
  runs on every push to `main`, on tags, and only on pull requests that touch
  `app/android/**`, `build-logic/**`, `gradle/**`, `gradle.properties`, `gradlew`,
  `settings.gradle.kts`, any `build.gradle.kts` or the workflow, because it costs two release
  builds and almost only build changes break determinism. A change to the app's code alone is
  checked after the merge.
- **(orchestrator)** ADR-0019: the JDK is pinned to major version 21, not a vendor or update;
  CI builds once with Temurin and once with Zulu to show that it does not matter.

CI:

- **(orchestrator)** Without an ADR, in `ci.yml` and [PLAN.md §8](../PLAN.md#8-quality-bar):
  **device tests run on every pull request**, on API 26 and 36, because the repository is
  public, so runner minutes cost nothing, and both finish before `check`, so a pull request
  waits no longer. They are not a required check.
- **(orchestrator)** Without an ADR, in `ci.yml` (commit `52ddd77`, #17): **`check`'s timeout
  is 60 minutes**, up from 45. It had been measured at 21 to 32 minutes, M4's run took
  30 m 44 s against the old 45, and `app:android`'s host tests and lint joined it in M5.

Process:

- **(orchestrator)** Without an ADR: #16 to #19 were merged with merge commits, as in M4. #19
  was merged before #18, which then merged `main` into its branch (`ecc3822`).

## Known limitations and what was not verified

What has not been verified:

- **The exit criterion**, and with it: **a real phone**, **a real tailnet** and **Tailscale's
  Android app**. The emulators have no VPN, so only the refusal side of the Tailscale check ran
  on a device; socket binding and route checks ran against the emulator's own network, and
  MagicDNS names were never looked up.
- **WebDAV from a device.** The WebDAV client is the desktop's code; on devices it ran only
  against a server on loopback inside the test process (#16), never a real server, and never
  over TLS. Whether Ktor's CIO does TLS on Android is untested.
- **Doze, App Standby and a frozen process**: when Android actually runs the jobs, and
  whether a sync after edits gets out before the process ends.
- **Auto Backup and device transfer.** The rules are written, not exercised.
- **`fdroid lint`, `fdroid build` and `fdroid scanner`** have not been run, nor the recipe on
  F-Droid's build server image. The reproducible check runs on Linux x86_64 only.
- **The recipe's TODOs**: the release tag in `commit`, `AllowedAPKSigningKeys` (the
  maintainer's certificate), and the `sudo` lines that install JDK 21 from Debian trixie, to
  check against the build server's current image. No release exists yet, so the `Binaries` URL
  points at nothing.
- **No screenshots** in the store listing.
- **Directory `fsync` on Android**: whether it syncs or fails as "not supported" and is
  tolerated, on either storage, was not checked (ADR-0012).
- **`content://` folders** are not supported at all.
- **How the screens look on a phone.** The device tests drive them; the demo's screenshots on a
  1080 × 1920 emulator are the only time anyone looked. Rows such as the note list's filters
  were not checked on a narrow screen.
- **`app:shared-ui`'s own tests on a device**: they run on the JVM only; the app's device tests
  cover its screens from outside.
- **A signed release**, `apksigner verify` and `apksigcopier compare`: no keystore was made.
- **The desktop app in a window**, still not opened since M2.

Known limitations:

- **Another app's VPN** holding an address in `100.64.0.0/10` passes the Tailscale check, and
  its routes then carry the token; Android does not say whose VPN it is (ADR-0018).
- No USB stick, SD card or Syncthing folder on Android in v1.
- Every 15 minutes is WorkManager's floor, and Android may stretch it; sync after edits needs
  the process to live 5 s, or the job after leaving the screen to run.
- On Android 8.0 and 8.1 nothing is backed up. A restored phone asks for its passwords again.
- No sync before the first unlock after a reboot; after it, the key works while locked.
- Two HTTP engines: CIO for WebDAV and loopback, OkHttp for the hub on the tailnet.
- Android itself refuses a share of about 330,000 characters or more (one binder transaction
  of 1 MB); 110,000 are tested.
- An emoji newer than the phone's Android shows as a blank box.
- The APK is about 16 MB, unshrunk. A forgotten `versionCode` bump is caught only by Android
  refusing the update or by F-Droid's checker.
- The debug and a self-signed release APK share an application id but not a signature:
  switching means uninstalling, which deletes the phone's notes.
- `hub-e2e.sh` runs by hand: CI runs the device tests, not the PC's half on the host.
- A pairing token is long to type on a phone; there is no QR code or link yet (ADR-0015).

## What M6 needs from M5

- **The exit criteria of M4 and M5**, run by the maintainer with the checklists above. M5's
  WebDAV leg is the first use of TLS from Android.
- **The first release** ([docs/releasing.md](../releasing.md)): a keystore, `v0.1.0` or
  `v1.0.0` tagged with the version literals raised to match, the signed APK attached to a GitHub
  release as `jotter-VERSION.apk`, and `apksigcopier compare` against the unsigned build.
- **F-Droid**: fill in the recipe's TODOs, run `fdroid lint`, `fdroid build` and
  `fdroid scanner`, add screenshots, and open the fdroiddata merge request
  ([docs/fdroid](../fdroid/README.md)).
- **The desktop's packages**: M6's criterion asks for an AppImage or Flatpak beside the APK,
  and CI does not build the desktop distributable yet.
- **M6's own scope** ([PLAN.md §10](../PLAN.md#10-milestones)): ADR-0007 (encryption) and
  ADR-0008 (multi-user), debug log export, error states, backup and restore docs, including
  what Android's backups hold and that secrets are never in them, and a user guide that covers
  pairing a phone over Tailscale and why folders are missing on Android.
- **Open choices for later**: a SAF folder backend with its own publishing rules and ADR;
  R8 with keep rules and device tests of a release build; a QR code or link for pairing.
- **The maintainer's review** of ADR-0018 and ADR-0019 and of the decisions above.
